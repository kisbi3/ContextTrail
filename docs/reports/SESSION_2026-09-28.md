### 4.1 "죽은 테스트 87개"

`langgraph`가 없는 환경에서 87개가 실패한 것을 죽은 테스트라 불렀다. **틀렸다.** `pyproject.toml`이 `langgraph`를 필수 의존성으로 선언하므로 정상 설치라면 322개 전부 통과한다. 내 환경 문제였다.

### 4.2 "LangGraph를 빼라"

"설치 시 82MB·51 패키지"를 근거로 **필수 의존성에서 빼자**고 권했다. 사용자의 이유를 듣지 못한 채 추천한 것이다. 그-layer는 Studio에서 모델의 의사결정 과정을 눈으로 보기 위한 LLMOps 계층이었고, 사용자는 유지하기로 했다. 실행 엔진에서 관찰 계층을 분리하면 **둘 다 유지하면서** 일반 사용자의 설치 부담만 줄일 수 있었는데, 그 구분을 하지 않은 채 제거만 권했다. 선택지 자체를 제대로 제시하지 못한 것이다.

### 4.3 "queue-operation 473건 사용자 요청 손실"

실측 전이라 위험성을 과장했다. 실제로 세어보니:

```
enqueue 473건
├─ 338건  user 레코드에 그대로 있음 (중복)
└─ 135건  없음
   ├─ 110건  Claude가 만든 합성 블록 (task-notification 등)
   └─  25건  사람이 직접 친 말 → 대부분 `sh .../scratchpad/*.sh`
```

사람이 직접 친 것은 25건이었고, 확인한 10건 중 7건 이상이 `sh .../scratchpad/*.sh` 형태였다. 나머지는 `/init`, `왜 막혀있어?` 같은 짧은 것이었다. **25건에 무엇이 들어 있었는지는 전부 읽지 않았다.** 그래서 "정보량 0"이라고 한 건 나중 확인 없이 한 말이고, 정당하지 않다. 확실한 것은 **473건이라는 규모**였을 뿐이다.

### 4.4 검수가 잡은 것

`gpt-6-sol`로 검수를 6회 돌렸다. 주요 지적:

**내가 만든 회귀 3건 + 크래시 1건**

- `attachment`가 dict가 아니면 `.get()`이 예외
- 경로 라벨 충돌로 경고 2개가 1개로 병합

**계약 변경**
- 일괄 조회가 `null`/`{}` 레코드를 보고하게 되어 "빈 키 = 증거 없음"으로 읽던 호출자 의미가 바뀜 → 되돌림

**"수정을 되돌려도 통과하는 테스트"**
