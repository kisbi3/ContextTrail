# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ContextTrail (PyPI package, import name and command `contexttrail`, short alias `ct`; the earlier working name `projectflow` survives only in compatibility identifiers: an existing `.git/projectflow/` state directory is still used, `projectflow-eval-v1` fixtures still load, and the tool's own `projectflow-run-` runner sessions stay excluded) reads local Codex, Claude Code and opencode transcripts plus Git history for one project, and uses an LLM (via the installed Codex or Claude CLI, sandboxed) to reconstruct an evidence-linked graph of goals, attempts, failures, and decisions. It is a development alpha (`0.1.0a8`). The README is English; most `docs/` are Korean. Console entry points `project`, `contexttrail`, and `contexttrail` all map to `contexttrail.cli:main`. With no command (or with a folder as the first argument) the CLI runs `view` on the current (or given) folder (`cli._default_command`); it never defaults to `analyze`.

## Commands

```bash
python -m pip install -e '.[dev]'          # add ,studio or ,langsmith extras as needed
scripts/test.sh -q                          # full suite; sets PYTEST_DISABLE_PLUGIN_AUTOLOAD=1
scripts/test.sh tests/test_engine.py -q     # one file
scripts/test.sh tests/test_engine.py::test_name -q   # one test
scripts/contexttrail demo --path /tmp/contexttrail-demo --no-tui   # source-tree launcher; synthetic data + Mock Runner, no AI
scripts/contexttrail view /tmp/contexttrail-demo/sample-project
scripts/contexttrail scan /path/to/project       # input selection diagnostics, zero runner calls
scripts/contexttrail eval --fixture demo --runner mock --output /tmp/pf-eval   # offline eval, writes review.html; economy like analyze (--no-economy for the full path)
python scripts/prelive_walkthrough.py --output /tmp/pf-prelive-walkthrough
python scripts/compare_models.py PROJECT --models claude:haiku claude:sonnet codex:gpt-luna codex:gpt-sol --units 5 --output /tmp/ct-compare --yes   # real models (needs consent): same units, one state copy per model
```

There is no linter/formatter configured. Tests use synthetic transcripts in temp dirs, loopback HTTP, and PTYs; they never call real AI accounts. Keep it that way — do not run `analyze`, `eval --runner codex|claude`, or `doctor --smoke` against real accounts without the user's explicit consent (they send data to a model service). Write any output/demo artifacts outside the repo.

## Architecture

**Pipeline (one engine, three log sources, two runners):**

1. `git_context.Scope.resolve()` normalizes the target folder, finds the Git common dir and linked worktrees. Path containment is by path components (`/app` ≠ `/app-backup`). State lives at `<git-common-dir>/contexttrail/<scope-key>/` (or `<folder>/.contexttrail/` without Git).
2. `sources/local.py` parses Codex (`CODEX_HOME`/`~/.codex` `sessions/`, `archived_sessions/`) and Claude (`CLAUDE_CONFIG_DIR`/`~/.claude` `projects/`) JSONL into `model.SourceRecord`s, attributing each record to the scope by recorded `cwd`/`workdir` only — never by keyword guessing. `sources/opencode.py` does the same for opencode's SQLite database (`--opencode-home`, else `$XDG_DATA_HOME/opencode`, else `~/.local/share/opencode`; every `opencode*.db` plus `OPENCODE_DB`), opened `mode=ro` + `query_only`, reading only `session`/`message`/`part` (the file also holds credential tables); a session is in scope by `session.directory` (a bash `workdir` overrides per call), `parent_id` plus the parent's `task` call give sub-agent lineage, a `compaction` part is the unit boundary and the `summary: true` assistant message after it is the summary, `synthetic`/`ignored` user text is metadata, reasoning is never collected, and `patch` parts become a metadata list of changed files. Its tool names are lowercase (`edit`/`write`/`read`/`bash`/`task`), so `EDIT_TOOL_NAMES`, `READ_TOOLS`, `DELEGATE_TOOLS` and the `filePath` key cover them. Tests build a synthetic `opencode.db`; the suite points `XDG_DATA_HOME` at a temp dir so no test opens a real one. Out-of-scope content is never sent to the LLM. Long records are split into ≤32k-char fragments (`segment_record`), binary payloads (including Codex `input_image` data URLs) replaced by digest markers. A forked Codex sub-agent's rows before `subagent_history_start_ordinal` are its parent's history and are skipped; a mid-file Codex compaction keeps its summary but not its `replacement_history` copy. Each record keeps who wrote it as its log says, `SourceRecord.authoring` (`model`, `effort`, `provider`; never guessed, empty when the log says nothing): Codex `turn_context` (`_codex_authoring`: the latest context before the record; Codex writes it before the person's prompt of that turn, so only the instructions injected before the first context stay empty) plus `session_meta.model_provider`, Claude Code assistant `message.model` with `perTurnEffort`/`effort` (a `<synthetic>` message has none; a tool result follows its call), opencode `providerID`/`modelID`/`variant` (a person's message from its `model`). It is outside the content hash (a later scan fills it in without re-sending a unit; `ingest` compares metadata) and in `HIDDEN_RECORD_FIELDS`, so the model never sees it. A session run with no person (`codex exec`: `session_meta` `originator: codex_exec`/`source: exec`; `claude -p` or an SDK: rows with `entrypoint: sdk-*`) gets `lineage.kind = unattended` with the tool as `agent_type`, so its user-role messages are not the person's (`is_user_prompt`); when its session ID appears in another session's tool call or result (`thread.started`, `session_id`), `_link_called_tools` (end of `collect_logs`) turns it into that call's sub-agent (`kind = subagent`, parent ids, `agent_type` kept). Lineage is in the content hash, so records newly read this way are analysed once more. A Claude Code session forked from another (`--fork-session`, resume) starts with a copy of the parent's recent rows (same `uuid`, the new session ID written over them): `_drop_forked_copies` (end of `collect_logs`, before `_link_called_tools`) drops a copy whose original is present (the parent is the session whose unshared rows start first; a fork with no parent here keeps its copies) and sets `SourceRecord.fork` (`from_session_id`, `point_at`: the last copied row's time) on the fork's own records, outside the content hash and hidden from the model. At publish, `schema.link_forks` hangs the fork's first request under the parent's last request before the fork point as a structural `follows` of origin `fork` with `fork_point_at` (drawn and listed as `갈라짐`/forked, never a cause). In the flow, when both the parent and the fork went on, the story up to the fork is one column and then the sides are drawn next to each other under a splitter (`diagram.branches_of`, `lanes_for`, `splitter`; a side has no margin rails, cross-side links are notes); with room for boxes at least `WIDE_BOX` (30) cells wide beside a side, results and sub-agent stacks stand beside its steps, else they fold into the step's box (status line, one magenta line per sub-agent event). Codex person-made forks copy nothing (`history_base`); Codex sub-agent forks skip the inherited rows.
3. `analysis.Engine` plans WorkUnits (by session/worktree, split on compaction, ≥3h gaps, window bounded by `unit_cost` and an estimated assembled payload (`estimated_payload`, 60% of `task_chars`), cut at the best safe boundary: after a successful commit result > before a person's message > after a run/test/commit/vcs result, never inside a tool call/result pair, so edit → run → result stay in one piece; stored `parsed` units with no result are re-cut under the current rule and the old ones marked `superseded`, `draft`/`extracted` never; an integrated unit is re-planned only when one of its own records changed, never for context it merely saw), and `analysis.Harness` builds tasks, serves model `ReadRequest`s for extra evidence, and runs bounded repair. Stages: **extract** (candidates + quoted evidence per unit, parallelizable up to `workers`; with one worker the next unit is extracted in the background while the current one integrates, `studio_graph._prefetch_next`, skipped for a shared runner, a nearly spent budget, or when no integrate call follows (`draft_only`, the economy default: the extraction is then the only call that can link a unit to the events before it, so it is built after they are published; workers above one still extract side by side)) → **integrate** (serial, produces a GraphDelta against the current graph) → optional **semantic review** only when the delta raises `review_issues` (an `unlinked_observed_outcome` issue is settled in code, `resolved_in_code`, when the delta adds no `CHANGE_KINDS` event, since the answer is then always "nothing to link") → **request turns** (code, no model; see below). `Harness.task` sends the Runner short IDs (`IdAliases`: `S12` for `src_…`, `E3` for `ev_…`, whole string values only) and maps the reply back before any check, so everything stored uses full IDs. Long tool results, injected text and summaries go into the extract input as head and tail only (`_view`, `omitted` range readable via `read_records`; results of read-only calls get a 400/200-char head and tail); the person's messages, assistant text and tool calls always go whole, but every shown line longer than `LINE_CHARS` (1,500) keeps its head and its last `LINE_TAIL_CHARS` (400) with a note between (`shown_line`, counted by `unit_cost`; Codex Desktop writes a whole command on one line and what it ran comes last). A saved quote is the whole cited lines with the cited part as `focus`; the model is shown that part within `SHOWN_QUOTE_CHARS` (300) (`shown_quote` in `_prompt_evidence`, marked `quote_is_part_of_lines`, and in the candidates the integrator sees, `candidates_for_model`), and a quote copied from it resolves to the same lines. The extract input also carries `skeleton` (the code-built steps of `light.skeleton`, which `extract.md` asks the model to keep as candidates and add to; since 2026-10-16), `user_requests` and `tool_steps` (`extract_request_data`, shared with the input preview): an outline of each tool call with an edit/read/run hint (run is refined to commit/test/vcs from the command line, `analysis.command_kind`, which leaves a heredoc's body out as data but reads the commands after its terminator, `drop_heredoc_bodies`; agent-coordination tools are `delegate`, a Codex `exec` that only calls `write_stdin` is `poll`, `web__run` is read). The selection audit (`context_selection`) stays with the ledger and preview; `model_context` keeps it out of the model payload. Every certain file edit (`hint=edit`, not failed) must be cited by some extracted event, via `required_citations`.
4. `schema.py` holds the JSON contracts, verifies that every cited quote actually exists in source (a citation is a line range; `quote` is optional, and `EvidenceValidator.fill_cut_quotes` keeps the shown lines within the range, at most `CUT_QUOTE_LINES`, as the quote when it is left out, `quote_cut_by_code`, so a wrongly copied quote is no longer a repair cause), and applies GraphDelta. Model output must pass this validation before it is stored or rendered. Only slips with a single possible reading are corrected in code and audited (`normalizations`): an exact quote at the wrong lines within lines the model was shown, a quote with one extra layer of escaping, event provenance fields (`recorded_at`, session/worktree ids) read from the cited sources, a `verifies`/`answers` written in reverse, a person's `goal`/`proposal` that an `answers` edge leaves (→ `question`/asked), an `actor=user` event resting only on user-role messages a calling agent wrote (a sub-agent's instructions, an unattended run's prompt; removed with its relations, `drop_caller_instructions`), a quote under `SHORT_QUOTE_CHARS` that appears exactly once in its cited lines, a quote off by whitespace, `...`-joined pieces or a run past a line end (each only when it has one reading in the cited lines), a quote repeated within 3 lines of the lines the model itself cited (stored as the lines holding every copy, `REPEAT_SPAN_MAX_LINES`; repeats farther apart are rejected with their line numbers for the repair), an integrated event whose `tool_record`/`observed_*`/`git_artifact` claim lost the tool or Git citation its own candidate carried (`restore_tool_evidence`), and a candidate resolved as `duplicate`/`updated` of items the same delta adds (→ `added`, `settle_in_delta_duplicates`). One claim is removed rather than repaired: a `verifies` between a documentation-only change and a run whose command never names that file (`drop_unchecked_doc_verifies`, noted in limitations); `tool_steps` flags such edits with `doc: true`. Claims a candidate's own citations do not back are read as the weaker claim they back (`settle_unbacked_claims`: unbacked `applied`/`observed_*` → `reported_complete`, unbacked `tool_record` basis → `git_artifact`/`explicit_statement`), and an extracted relation that breaks a `check_relation` rule is dropped into limitations (`drop_rule_breaking_relations`), both to save a whole-unit repair. Everything else is rejected into the one repair round; if the repaired extraction still fails, `salvage_extraction` keeps the candidates that pass on their own, names the dropped ones in limitations, and waives a required edit citation only when a dropped event had cited it.
5. `store.py` (SQLite in WAL mode, so the screen and browser keep reading during an analysis, + lock) publishes a new consistent graph version atomically (each version a whole graph, zlib-compressed behind `GRAPH_MARK` since state schema 2; text versions of schema 1 are packed once on open) and keeps the `llm_calls` ledger. Completed units (including empty extractions) are never re-sent; re-running with no new records is a no-op with 0 runner calls, and `ingest` writes only rows that changed.

**A failing unit is skipped, not fatal.** A full extraction still invalid after the one repair round, when `salvage_extraction` keeps nothing either, is first read the light way (`Engine._extract_unit` `read_light`: code-built skeleton, one `light` call, code-cut citations; `LIGHT_FALLBACK_LIMITATION` in the unit's limitations, not in an audit); only when that is refused too is the unit skipped. In a CLI run `studio_graph._skippable` wraps the unit-level nodes: a `TaskValidationError` (still invalid after the one repair round and the light reading) or an `InputBudgetExceeded` (over `task_chars` with nothing left to trim) records the unit in the `unit_failures` meta (`_skip_unit`: kind, message, `Engine.failure_input` = routing signature + record hashes, integrated-unit count), the unit's remaining nodes pass, and `advance_unit` moves on; the run ends `partial`, or `failed` if no unit completed. `Engine._hold_back_failed` (at the end of both planners) leaves out a unit with the same signature and hashes unless `retry_failed`, and supersedes one whose session has notes; a retried unit joins `out_of_order_events` when other units were integrated since. Runner errors (`FlowError`), `CallLimitReached`, `Cancelled` and unknown exceptions are not skippable and stop the run; `BrokenOutput` (unreadable final JSON) is retried once inside `Harness.task`; any other exception a check raises on an answer is that answer's refusal (`answer check failed in code (<type>): …`, recorded with the call, repair round), never a stopped run. The calls of one `Harness.task` share the runner's conversation (`runner.thread()`: Codex persists the `exec` session in the run's temporary home instead of `--ephemeral` and follow-ups run `codex exec resume`; Claude runs the first call with `--session-id` instead of `--no-session-persistence` and follow-ups with `--resume`; a follow-up carries only `new_evidence_rounds`/`repair`/`evidence_requests`, `Thread.follow_up`; a failed call resets it; usage of a resumed Codex call is the difference from the session's running total, a Claude call's is its own), and with the hidden `--unit-thread` (off: sharing measured a net loss in time, `docs/plans/PERFORMANCE_PLAN.md` §21) the stages of one unit share it too (`Engine.unit_thread(unit_id, runner)`, passed as `thread=` to `Harness.task` for extract, integrate and the delta review when they use the same adapter, tool and model; a later stage is a follow-up under `STAGE_FOLLOW_UP` whose data leaves out the keys the session's first request already holds, named in `already_in_conversation`; the same stage asked differently or other instructions — the light reading — start a new session; `advance_unit`/`finish_run` close it). On Linux the sandbox binds `<temp>/sessions` to `/pf-home/.codex/sessions` for this. After the last evidence round (`read_rounds`, 2; `--economy` sets 1) the next call's schema allows only `complete` (`final_schema`) and the request carries `evidence_requests: READS_USED_UP`, so a model that keeps asking answers instead of failing the unit. `_can_start` (the routers) refuses a unit when the calls left are fewer than `MIN_UNIT_CALLS` (one if its saved extraction is valid); with no unit completed the status is `call_limit` (exit 2). The runner's `preflight` runs after the consent, before the first unit. `freshness` reports `failed_units` apart from `pending`. Messages: `skipped_unit_message`/`held_back_message`, English, in the `informational` list.

**Orchestration is a LangGraph graph.** `Engine.analyze()` delegates to `studio_graph.run_engine`, so the terminal CLI, `contexttrail eval`, and LangGraph Studio (`langgraph.json` → `studio_graph.py:graph`) all execute the same compiled node sequence (`prepare_run → scan_sources → classify_steps → plan_work_units → select_unit → prepare_extract_input → extract_model_and_validate → validate_candidates → prepare_integrate_input → integrate_model_and_validate → route_semantic_review → [semantic_review_model_validate] → link_request_turns → summarize_graph_changes → publish_result → advance_unit → finish_run`). Changes to analysis flow usually touch both `analysis.py` (primitives) and `studio_graph.py` (node wiring/state).

**Runners** (`runners/cli_runner.py`): wrap the user's installed `codex`/`claude` CLI inside an isolation sandbox — bubblewrap on Linux, a deny-default `sandbox-exec` profile with a temp HOME on macOS. Only file-based auth (`auth.json`, `.credentials.json`) is bind-mounted read-only (opencode is a log source only, never a runner); if the sandbox or required CLI flags are unavailable the runner refuses to run (no unsandboxed fallback). `routing.py` provides the per-role runner pool and the host call budget (`--max-calls`, default 30; with a unit count it is `CALLS_PER_UNIT`×units unless `--max-calls` was given; per run, never saved). Before sending, a run shows `plan_summary`/`plan_text`/`plan_choices_text` (units, calls, tokens and minutes for 5/15/30 units; ×3 of the character estimate, or calibrated from ≥3 past units in the ledger) and asks via the `consent(snapshot, plan)` callback, which may answer with a unit count; the TUI asks from the analysis thread through `TerminalApp.confirm`/`ask_units`. `--units N` fixes the count; `--session <id>|current` plans only that session and its sub-agents (events land in the graph's `out_of_order_events`). `--recent N` / `--since WHEN` (`AnalysisConfig.recent`/`since`, `analysis.recent_sessions`, `since_cutoff`; per run, never saved) widen that to several sessions through the same `family`/`in_scope` in `_plan_units` (`Engine._select_sessions`): the N most recent (latest record of the session and its sub-agents; a sub-agent follows its parent) of those without notes (sessions in `journal_sessions` are neither candidates nor counted), planned oldest first, and refused together with `--session`, `--audit` and `--trigger hook`; an empty selection is a `FlowError`. `Engine.ahead_of_order` (set by `_plan_units`: a record outside the chosen sessions still waits) decides `out_of_order_events` in `publish_result` for all three options, and `Engine.plan_fields` adds `plan.selection` (and the first line of `plan_text`) naming the sessions taken first. No model-visible text changes (`docs/plans/RECENT_SESSIONS_FIRST.md`). `scan` prints the plan without a model (`Engine.preview_plan`). A run always names its model (`DEFAULT_MODELS` in `cli_runner.py`; the sandbox hides the user's CLI config; Codex's default `gpt-luna` (Claude's `haiku`; the light models since 2026-10-17, measured against `gpt-sol`/`sonnet`), like any `gpt-<family>` without a version, is resolved in `preflight` to the newest listed `gpt-<version>-<family>` of `codex debug models --bundled` run in the sandbox, `newest_in_family`, and refused if none is found) and passes a per-role reasoning effort (`--extract-effort`/`--integrate-effort`/`--escalation-effort`); both are recorded per call. Stage models are chosen via `--extract-model`/`--integrate-model`/`--escalation-model`; never silently switch model or provider on failure. Delta review runs by default on code signals (`analysis.REVIEW_SIGNALS`); `--no-review` skips it for one run. `--context-mode` (hidden; default `lean`, `full` restores the old input) shrinks the extract context to a graph-shaped view (`existing_*`) plus cited lines ±3 (a block over `CITED_BLOCK_CHARS` keeps only the cited lines), 2 preceding records and up to 3 nearby records of the other source type shown head and tail (`CONTEXT_HEAD_CHARS`/`CONTEXT_TAIL_CHARS`), within `LEAN_CONTEXT_CHARS` (8,000), 6 related events and a 30-event index, and a small manifest; every shown record leaves out the fields only code uses (`HIDDEN_RECORD_FIELDS`, `record_for_model`); a wired request still over `task_chars` is trimmed step by step (`trim_step`, recorded as `input_trimmed`) and fails only when nothing is left to cut; `_routing_signature` includes the mode only when it is not the default, so finished units are not resent. Two more hidden options change only the integrate/review requests: `--integrate-evidence reuse` (opt-in) lets the integrator leave out evidence an input candidate already carries (`EvidenceValidator.reuse_candidate_evidence` fills it before every check), and `--review-output patch` (default since 2026-09-29; `full` restores the rewrite-the-whole-delta review) makes the delta review answer only its changes (`schema.merge_review_patch` folds them into the proposal, then the unchanged `apply_delta` runs). `--unit-summary` (hidden, per run, an experiment) adds `UNIT_SUMMARY_REQUEST` to the extract or light request and a `unit_summary` (string or null) to its schema (`with_unit_summary`; taken out before the checks by `take_summary`, kept in the unit's cached result); `publish_result` stores it in `graph["unit_summaries"][unit_id]` with the event IDs the unit added, and the flow draws it as `구간 · …` above the first of them in the story column; off, the request and the signature are unchanged. `--pipeline v2` (hidden, per run, an experiment, `docs/plans/PIPELINE_V2.md`) replaces the extract call with one `story` call (`prompts/story.md`, its own system prompt like light): code keeps `light.skeleton` as the record of the work (edits, checks, commits, `covers` links), `light.story_request` sends no tool output, only what the person and the assistant wrote cut into evidence blocks (`blocks.py`, `written_blocks`; a model cites `B12`, code turns it into exact lines with `light.cite`), the work outline with failed runs' last lines (plus the other runs as `R1`… items, `light.run_items`, kept as events only when the story points at them) and the existing events; work the model leaves unnamed gets a code title in the output language (`light.code_title`: `수정:`/`검사 통과:`/`실행:`…); the answer (`STORY_SCHEMA`: work names, story events with blocks and work IDs, links, `turn_summary`) becomes an ordinary extraction (`story_extraction`); a story call that fails its checks leaves the work alone (`STORY_FALLBACK_LIMITATION`), the turn summary goes to `unit_summaries`, and the assistant's blocks no story event cites to `graph["unclaimed_reports"]`; `AnalysisConfig.validate` forces no integrate call and no review for it. `--light` (saved per project, `light.py`, `prompts/light.md`) replaces the extract call with one light call: code builds a skeleton from `tool_steps` (edits grouped per turn, test results failed by exit status via `check_failed`, commits, a structural `verifies` from a turn's last non-doc edit to a later test in that turn only when the run names every edited file, `light.covers`: each file or its module's test file (`test_calc.py`, `calc_test.go`, `calc.test.ts`, …) among the run's targets, compared as whole names (a whole-suite run, a `-k`/`-m` selection, a run naming only some of the files, or a name that merely contains the stem is no check of the edit, however close in time)), the model answers `LIGHT_SCHEMA` (skeleton titles/summaries plus narrative events citing source IDs and optional line ranges), and `light.extraction` turns that into an ordinary extraction with code-cut citations (`cite`, ≤20 shown lines); a refused candidate is salvaged away, never repaired; it implies `--economy`'s no-integrate, no-review publish and is not used by `--audit` (`Engine._light`). `--economy` is the default since 2026-10-16 (saved per project; `--no-economy` restores the integrate and review calls); `eval` follows it too (`cli._economy`; `eval --no-economy` for the full path): it sets `integrate_output="draft_only"` (the draft is published whenever it passes the checks, so no integrate call), turns the review off and allows one evidence round. `--integrate-output` (hidden; default `draft` since 2026-10-02, `full` restores the old request) does the same for integration: `patch` sends a code-built `draft_graph_delta` (`schema.draft_delta`: every candidate added as extracted, a candidate matched to exactly one existing event as its duplicate) and the integrator answers only its changes; `draft` publishes that draft with no integrate call while the graph is still empty (falling back to `patch` if the draft fails the checks). In both patch requests the model sees the delta through `schema.delta_for_model`: an added item that is its candidate unchanged is named (`{"id", "candidate": "unchanged"}`), and a candidate resolution or change attribution whose evidence is exactly its candidate's own is shown without that copy (the candidates are already in the request; `candidate_evidence` marks a quote a candidate carries as `quote_in_candidates`, `candidate_quotes`), which is what kept a dozen-candidate unit under `task_chars`; the full delta stays in code for the merge and the checks (`expand_for_model_view` is only for the fixture runner), and the patch schema still requires evidence on anything the model writes. The patch-mode review request is the integrate request without `context_only` and `manifest` (`REVIEW_OMITTED`); full mode is unchanged. Plan and measurements: `docs/plans/PERFORMANCE_PLAN.md`. `analysis.classify_steps` (node `classify_steps`, `scan` → `steps`) counts code-classified tool calls and the share of unplaced `run`s; no model call. `demo.py`'s Mock/Fixture runner is only for synthetic fixtures and must not be selectable for real projects.

**Prompts** are Markdown in `src/contexttrail/prompts/` (`common.md` + stage files `extract.md`, `integrate.md`, `repair.md`; `audit.md` is appended to the extract and integrate instructions only in an audit), written in English, loaded via `analysis.prompt()`/`build_task()`. They ship as package data along with `assets/`. The event grain the prompts ask for is a step (since 2026-10-15, `common.md` [Events]): the edits one check settled as one change, that check as the outcome that verifies it, plus each failure, change of method or withdrawal that turned the work; a repeated run of the same check and a report that restates recorded results are not events. `light.skeleton` folds a same-turn repeat of the same check command with no edit between into one result. Every task carries `output_language` (`Engine.resolve_language`: `--language`, else saved per project, else `detect_language` from the person's messages): titles and summaries are written in it, quotes and identifiers stay as written. Everything else the model reads is English too, since 2026-10-06: validation messages (the repair step matches them by pattern, `schema.QUOTE_MISMATCH_HEADS` and the mismatch regex in `Harness.task`; `evaluation.error_kinds` counts the code-written head before the first `:`, so a message keeps a short, distinct English head), the limitation and warning strings that enter the extract input as `input_limitations` (matched by the `informational` tuple in `analysis.py` to decide whether a re-run is a no-op), read-request `denied` reasons, review questions, and the text code writes into the graph (dialog-turn rationales, unit warnings, dropped-candidate notes). Changing any of them is a model-input change.

**Screen language** (`i18n.py`): everything the person reads on the terminal, in the TUI, in the browser view and in `find`/`show` output is Korean or English, chosen once per process by `i18n.resolve`: `--language`, else `CONTEXTTRAIL_LANGUAGE`, else the project's saved output language, else the locale (`LC_ALL`/`LC_MESSAGES`/`LANG`), else English. Code calls `tr(ko, en)` at use time (never at import); label tables are `i18n.Labels`, which pick the language on each lookup. The test suite pins Korean (`conftest.korean_screen`), and a test of the English screen sets `i18n.set_language("en")` itself. Text the model reads and text written into the graph (titles, summaries, rationales, limitations) do not follow the screen language.

it draws `diagram.flow_diagram` (boxes and labelled arrows in two lanes since 2026-10-18: the story on the left — requests, decisions, code changes, failures and claims in words — and the steps in between on the right — checks that passed, results resting only on test runs and documentation-only edits (`event.step`, `check`/`doc`, read off the cited records' `SourceRecord.step`, which `analysis.mark_steps` sets at scan and on a note's records, by `schema.fill_steps` at publish), sub-agents and runs of another model — each beside a main step (`Diagram.beside`): placed by a relation first (a check a step verifies leaves it on `─검증─▶`; a failure or claim that leads into a step stands beside it as its cause, `◀─동기─┤`), else by time within its own session (a check or edit beside the step before it, a sub-agent's work beside the step after it): such a box stands after the linked ones under a dim `┄ 같은 무렵 · 이어진 관계 없음` caption, joined by no line, never a cause; a decision box also shows the first sentence of its summary (`_first_sentence`, wrapped, never cut), its reason; a flow with no main step stays one column; with no right column (a fork's narrow sides) the right-hand boxes follow their step down the column; neighbouring story-column boxes with no relation are joined by a dotted unlabelled time-order line (`┊ ▽`, `then`/`then_down` glyphs; no link ids, never a cause); unrelated sessions are separate flows; text is wrapped, never cut; a box holds its title, status (`render.status_labels`; an observed result linked to no change reads `관측 성공 · 무엇을 검사했는지 연결 없음`) and written-in links only — who did the step (`render.agents_label`: the tool, and for the agent's own work its model and effort, from the event's `authoring`) and that a box has no link are in the detail pane since 2026-10-18, which `schema.fill_authoring` reads off the cited records' `SourceRecord.authoring` in `Store.publish` — for new events and for older ones whose records were read again, with the `role` (`subagent`/`unattended`) and sub-agent name from the records' lineage; a person's box names only the tool, a model's name drops the tool's prefix; a sub-agent's box or a called tool's says whose it is in the header (`render.delegate_label`: `결과 · 하위 Explore`, `결과 · codex exec`), has a magenta border (`sub` style) whatever its status, and stands in the right column beside the parent's next story step (the last one when nothing followed) as a stack joined by one line into that box, `◀──┬─Explore───┤` (`_sub_agent`, `_sub_label`, `delegated`; a run with no person and no known caller stays in the column)) and falls back to `render.terminal_graph` when the panel is too narrow. The analysis model that wrote an event (`analysis`: runner, model, effort from the ledger, stamped on a unit's new events in `publish_result`, `_analysis_of`) is shown only in the detail (`분석:`), `show` and `--json`, never in the flow. When the graph has user messages it shows one request's turn at a time (`diagram.request_turns`, `flow_diagram(only=…)`; `[` `]` move, `A` toggles the whole flow) with a request list on the left at ≥180 columns. Each `Cell` records the edge ids it draws (`Cell.edges`) so the selected box's links are lit and unlinked boxes dimmed. Event detail text comes from `render.event_detail` (`keys=True` numbers links 1–9 in `render.linked_events` order for number-key jumps, Backspace goes back), which non-TTY `contexttrail graph` output also prints without keys. All panel keys live in `FlowPanels.handle` and are listed by `?` (`ui.HELP`); keys typed in Korean input mode are mapped to their Latin key (`ui.latin`), and while help or a `/` search prompt is open `FlowPanels.modal()` routes every key to the panels before the screen's own R/B/Q. The mouse (off with `--no-mouse`) is clicks and wheel only; clicking a line or note follows its edge via `Cell.edges`. `langsmith_trace.py` (`--langsmith`, `--langsmith-content`) is a developer-only design aid, hidden from `--help`; it is not a user/deployment feature.

**Freshness** (`freshness.py`): `Engine.scan` saves a `source_index` (every transcript file's size and mtime as read, every in-scope opencode session's `time_updated`); `freshness.check` counts records the last scan ingested but no analysis processed (from the store) and, by parsing only new or changed files against that index, records written since the scan (`since_scan`: sessions, records, newest time, per source). `contexttrail status [--json]` prints it; `find`'s first line ends with `freshness.summary` (changed files parsed up to `FIND_BUDGET_BYTES`, else counted as "not parsed"); the TUI header and the browser status line show the same phrase once per graph version. The per-file counts of one check are kept in `freshness_cache`, keyed on the scan time and a digest of the stored records' hashes, so the next check re-reads only files that changed again (on this repository: 2.0 s → 0.3 s). `unaudited` (sessions and records `analyze --audit` would read, from the store alone) rides in the same result and header phrase. Only counts, never estimates; a full re-parse of this repository's logs takes about 47 s, which is why the index exists.

**Automatic analysis** (`auto_update.py`): opt-in per project. `contexttrail auto-update --enable --runner codex|claude --units N [--cooldown 15m] [--max-runs-per-day K]` saves `auto_update` meta and the runner consent; every host hook runs `contexttrail auto-update` (folder from `--folder` or the hook's stdin JSON `cwd`), which always exits 0, never creates state for a project without one, and spawns a detached child `auto-update --run --folder F` (new session, stdin closed, log `auto-update.log` 0600) only when enabled, unlocked, pending, past the cooldown, under the daily cap and not `failing`; the child runs `analyze … --yes --no-tui --brief --units N --trigger hook` in-process and records its exit in `auto_update_state.runs` (exit 0 and 2 are fine: `--units N` always leaves a partial run), so after `FAILURE_STOP` (3) failed runs in a row the hook starts nothing until `--enable` is run again (which clears the run history, not the day's start count); `AnalysisConfig.trigger` lands in the run manifest. `install-hooks --claude|--codex|--opencode` merges a `Stop` hook into `~/.claude/settings.json` (`async: true`) and `~/.codex/hooks.json`, and writes the `session.idle` plugin `~/.config/opencode/plugins/contexttrail.ts`; user entries are kept, ContextTrail's own are replaced only with `--force`.

**Notes** (`journal.py`, `contexttrail note`): the agent that did the work writes one event of its own session, with no model call. Each `--quote` is found in the current session's records only (`session_records`: the transcript file named by the session ID, or that opencode session, `parse_opencode(session=…)`; `quotable` drops the note calls and their output), as the most recent record holding it, and the event goes through `check_extraction` → `draft_delta` → `apply_delta` → `link_request_turns` → `publish` under the analysis lock (refused at once, never waiting, while an analysis runs; the CLI then queues it, below, and the reminder counts a queued note as written). Events and relations it writes carry `origin: "note"`; `--verifies/--revises/--answers/--motivates EVENT` add an explicit relation from that earlier event to the note. Records are stored with `Store.ingest(partial=True)`, which does not mark the project's other records unavailable. The session comes from `journal.current_session` (`CLAUDE_CODE_SESSION_ID` when `CLAUDECODE` is set, else the one of `CODEX_THREAD_ID`/`CLAUDE_CODE_SESSION_ID`/`OPENCODE_SESSION_ID` present), which `--session current` of `analyze` uses too. Notes are per project (`note --enable`; `journal` meta). A noted session leaves analysis from the notes' boundary on, except the records after its last note once it has been quiet for `TAIL_IDLE_SECONDS` (an hour): `Store.acknowledge_journaled` keeps that stretch in `journal_tails` and `in_journal(..., tails)` gives it back to analysis (the automatic analysis, `--trigger hook`, plans those units first, `Engine._tails_first`, out of order while older records wait) (`Store.journal_since`: the earlier of the first `note --enable` and the oldest record a note cites, kept as `journal.since`; `store.in_journal` is the one test, used by the store, `freshness`, the audit planner and the failed-unit hold-back): the note publishes those records as processed, `Store.note_session` records the session in `journal_sessions`, every scan runs `Store.acknowledge_journaled` (also for sub-agent sessions; it gives a noted session's older records back to analysis unless an integrated unit covers them), `_plan_units` supersedes a stored `parsed` unit with no result whose records are no longer pending, and `freshness` does not count them. A tool call is left out of the quotable records only when its shell command runs `note` (`runs_note`), not when it merely mentions it. The end-of-turn reminder is `note --hook` (synchronous `Stop` hook beside the async auto-update one, `NOTE_MARKER`; stdin `session_id`/`cwd`/`stop_hook_active`): it answers `{"decision": "block"}` once when the work since the last note is due (`journal.due`: `REMIND_CALLS` (10) calls, `REMIND_AFTER_SECONDS` (30 min) since the first, or a commit; read incrementally from the transcript by `_work_since`, which keeps its offset and the unnoted calls in `journal_activity` → `scan`, opencode parsed whole) and `unnoted_work`/`_is_work` finds edit/commit/test/vcs calls, or a `run` whose shell command writes a file (`writes_files`, quoted text ignored; a line whose every write lands on an absolute path outside the project, `write_targets`, and an edit of such a path are not counted), newer than the last note or reminder (`journal_activity`, in transcript time) and never creates state; its body runs under a per-project file lock (`_hook_lock`), since `install-hooks` and the plugin can both run it at one turn's end. An `observed_*` quote is looked up in tool results first and an `applied` one in tool calls and results first, before an assistant message repeating it. The opencode plugin sets `OPENCODE_SESSION_ID` in `shell.env` and posts the reminder with `client.session.prompt` on `session.idle`; the reminder text is in `model.HARNESS_TEXT`. The `contexttrail-note` skill is model-invocable. When the state cannot be written (Codex's workspace-write sandbox keeps `.git` read-only), `note` runs `prepare` (transcript-only checks; saved settings read through `ReadOnlyMeta`) and `queue`s the note under `$TMPDIR/contexttrail-notes/<scope>/` with a `q_…` id; `hook` runs `flush` first (oldest first, `q_` ids resolved through `aliases`, a note blocked by a running analysis stays queued) and blocks once with `REFUSED_REASON` for refusals, which `note --list` also shows. `--session current` resolves through `current_in_project`: the session variable of the nearest Codex/Claude Code/opencode ancestor process (`host_tool`, `ps`; a nested host inherits the outer one's variables, and Codex's sandbox refuses `ps`), else the first environment-named session with records in the project that holds every `--quote`, else the first with records (`OPENCODE_SESSION_ID` first). The suite stubs `host_tool` (`conftest.no_host_process`). The reminder hook stays quiet for a run with no person (`unattended`: Codex `session_meta` `originator: codex_exec`/`source: exec`, Claude Code `entrypoint` `sdk-*`). `plugin_files` generates the Claude Code plugin bundle (`.claude-plugin/marketplace.json`, `plugins/contexttrail/`) from the same skill text, using `contexttrail` on PATH; rerun `scripts/build_plugin.py` after changing skill text (a test compares). `analyze --audit` (`AnalysisConfig.audit`, per run, never saved, refused with `--trigger hook`; `scan --audit` previews it) is the other half: it re-reads the records of journaled sessions (and their sub-agents) that no `integrated` unit covers, planned by `Engine._plan_audit_units` into `audit_` units with the ordinary chunker, which `_plan_units` and `calibration` ignore. The extract and integrate requests carry `journal_audit.note_event_ids` (the note events citing the unit's records, forced into `existing_events` past the 12-event limit by `Harness.keep_events`) and `prompts/audit.md` is appended to the instructions only then, so an ordinary request is unchanged. `required_citations` leaves out edits some event already cites (`uncited_edits`), `add_user_requests` is skipped, a candidate with a note's kind and exactly its cited lines becomes an `existing_event_matches` entry (`match_noted_duplicates`), and `audit_guard` rejects any delta that updates, invalidates or resolves what exists. The semantic review is off, the run leaves `analysis_status`, `coverage` and `out_of_order_events` alone, its status counts only audit units left, and what it adds carries `origin: "audit"`. Plan: `docs/plans/LIVE_JOURNAL.md` (§11 is the audit). The reminder names the calls it is about (`journal.reminder_text`, `describe_work`): the most recent distinct calls from `unnoted_work`, at most `REMINDER_CALLS` (5), each as the `step_hint` kind (edit/test/commit/vcs/run) and a short target (the edited file, or `REMINDER_CHARS` (80) characters of the command, never output), with "… and N more earlier" after them; its first sentence stays as `REMINDER` has it (`HARNESS_TEXT` matches it), and the opencode plugin posts the hook's `reason` unchanged.

**Session memory** (`session_context.py`, `contexttrail context`): the saved graph's summary given to the agent when a session starts, with no model call. Per project and opt-in (`context --enable`/`--disable`, meta `session_context`; `context [folder]` previews the text). `context --hook` is the entry point of the host's start hook (Claude Code and Codex `SessionStart`, answer `{"hookSpecificOutput": {"hookEventName": "SessionStart", "additionalContext": …}}`, the same shape for both; opencode's plugin posts it on `session.created` for top-level sessions through `client.session.prompt` with `noReply: true`); `install-hooks` merges it beside the Stop hooks with `auto_update._merge_hooks` (marker `CONTEXT_MARKER`, synchronous, `timeout` 10), `plugin_files` puts it into the plugin bundle. It prints nothing, creates nothing and exits 0 unless the project is opened and has it on. It opens the state with `store.ReadOnlyStore` (`mode=ro`, `immutable` when no `-wal`/`-shm` exists so no side file is left), never parses a transcript or reads every record: `freshness.lag` counts pending records in SQL (same number as `freshness.stored`, tested) and `freshness.cached_since_scan` adds the since-scan count an earlier `find`/`status` left in `freshness_cache` for the same scan. Choice and order reuse `agent_view.newest_first`/`event_row` and `render.status_labels`/`status_tones`: recent decision/action/revision events, open items, failed attempts without a later `revises`; at most `MAX_CHARS` (2,000) characters, English whatever the screen language (`session_context.english`). The text starts with `model.SESSION_CONTEXT_HEAD` (also in `HARNESS_TEXT`, since opencode posts it as a user message), then `agent_view.memory_note`, then a fenced data block; model-written titles are one quoted JSON string each and a status label that names a check is cut before that check's title (`docs/SECURITY.md`). Two copies of the hook (`install-hooks` plus the plugin) give a session its memory once (`first_time`, a lock and a mark in the state directory for 120 s). `source` is read for that key only; resumed sessions are not skipped (unverified). Plan and the record of what was checked in each tool: `docs/plans/SESSION_START_CONTEXT.md`.

`agent_commands.py` installs the `contexttrail-update` / `contexttrail-context` skills into the user's Codex and Claude Code config and the same two as opencode custom commands (`~/.config/opencode/commands/`, `contexttrail install-commands`); it must not overwrite user-authored files without `--force`. Agents use the CLI, not MCP: `find`/`show`/`status` (`agent_view.py`, `freshness.py`; saved graph only, quotes fenced as data, `--json`) and, for update, `scan` (always JSON; `--json` is accepted) which reports the project's saved `runner` then `analyze --runner <saved or user-chosen codex|claude> --units N` with the count the user gave; opencode is never a runner. Update is explicit-only (Claude `disable-model-invocation`, Codex `agents/openai.yaml` policy; opencode commands are user-typed only, and since opencode also reads `~/.claude/skills` the installer prints an `OPENCODE_PERMISSION_HINT` for `opencode.json` rather than editing it); context may be picked by the agent. The TUI `y` key and the browser button copy a `contexttrail:ev_…@vN` reference for pasting into an agent chat.

## Invariants to preserve

- Read-only toward inputs: never modify the project, transcripts, or Git refs/index/config; Git is queried with argument arrays and `--no-ext-diff`/`--no-textconv`, pager off. The tool's own state/export dirs are excluded from change analysis.
- Analysis runs only on explicit request; viewing, export, page load, and node selection never trigger model calls.
- Prefer explicit partial/failed states over fabricated completeness; proximity in time is not treated as causality.
- A change never carries a success badge: `observed_*` statuses are only for `outcome` events, and a change (`action`/`revision`) is shown as verified only through a non-inferred `verifies` edge to such an outcome. Every message the user typed (`model.is_user_prompt`: user role, not harness-injected text (`HARNESS_TEXT`, including Claude Code's sub-agent hand-backs and usage-limit notices; a leading `[Image: original …]` note, `IMAGE_NOTE`, is set aside) or a sub-agent) is a user event; questions and requests are `question`/`asked` (shown as 요청), answered via `answers` edges. When the model skips one, code adds it (`add_user_requests` before integration, `link_request_turns` after). `link_request_turns` also hangs each new event that no relation reaches from the user message of its turn in the same session (a sub-agent's work: the parent session's message just before it), as `follows` with basis `structural` and `origin: "dialog_turn"` (drawn as one bracket per message, labelled 대화 순서 in details): dialog structure, never a cause. Display labels are derived from these edges (`render.status_labels`).
- State dirs are `0700`, DB/exports `0600`. Transcripts, evidence exports, and browser access links are sensitive. Read `docs/SECURITY.md` before touching CLI isolation, auth handling, or browser endpoints.
